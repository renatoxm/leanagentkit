# AGENTS.md

> Instructions for AI coding agents working on **this repository** — the source of
> the `create-lean-agent-kit` npm package. Do not confuse this file with
> `template/core/AGENTS.md`, which is the template shipped to end users.

## 1. What this project is

Lean Agent Kit is a scaffolder that installs a small Markdown "memory" (AGENTS.md,
codebase map, active context, session skills) into other projects so AI coding
agents can resume work without re-scanning the repo. This repo contains the CLI
(`bin/`), the install payload (`template/`), the test suite (`test/`), and a
VitePress documentation site (`docs/`).

## 2. Stack & tooling

- **Runtime:** Node.js >= 24, ESM only (`"type": "module"`), `.mjs` files
- **Package manager:** pnpm (repo root and `docs/` are separate packages, no workspace)
- **Runtime dependencies:** none, by design — the CLI uses only `node:` built-ins
- **Dev tooling:** node built-in test runner, Prettier (Markdown only), husky +
  commitlint (Conventional Commits), commit-and-tag-version for releases
- **Docs:** VitePress site in `docs/`, deployed to GitHub Pages

## 3. Commands

| Action        | Command                                           |
| ------------- | ------------------------------------------------- |
| Install       | `pnpm install`                                    |
| Test          | `pnpm test` (node --test, runs `test/*.test.mjs`) |
| Format        | `pnpm format` (Prettier, Markdown only)           |
| Format check  | `pnpm format:check`                               |
| Try the CLI   | `node bin/cli.mjs /tmp/test-target`               |
| Commit helper | `pnpm commit` (commitizen)                        |
| Release       | `pnpm release` (commit-and-tag-version)           |
| Docs dev      | `cd docs && pnpm install && pnpm docs:dev`        |
| Docs build    | `cd docs && pnpm docs:build`                      |

## 4. Layout

| Path                       | Role                                                                 |
| -------------------------- | -------------------------------------------------------------------- |
| `bin/cli.mjs`              | Thin npx entry; real logic lives in `bin/lak.mjs`                    |
| `bin/lak.mjs`              | All CLI logic, exported as named functions so tests can import them  |
| `template/core/`           | Default install payload (copied verbatim into target projects)       |
| `template/packs/`          | Opt-in pack overlays; `manifest.json` + one `pack.json` per pack     |
| `test/`                    | Node test files; `test/helpers/skills.mjs` shared helpers            |
| `docs/`                    | VitePress site (own `package.json`; **not** published to npm)        |
| `docs/.vitepress/sync.mjs` | Generates `docs/guide.md` and `docs/stacks.md` from template sources |

Only `bin/` and `template/` ship to npm (see `files` in `package.json`).

## 5. Conventions

- Keep the CLI **zero-dependency**: never add runtime deps to the root
  `package.json`; use `node:` built-ins in `bin/`.
- New CLI behavior goes in `bin/lak.mjs` as an exported function so tests can
  drive it directly (see `createFakePrompts` for wizard testing).
- Template and manifest must stay in sync: `pack.json` `files` lists every file a
  pack installs; `manifest.json` mirrors pack ids, deps, and skills. Tests like
  `registry-parity.test.mjs` and `meta-skills.test.mjs` enforce parity — run
  `pnpm test` after touching `template/`.
- Skills follow the `leanagentkit-<name>.md` naming under `.agent/skills/`.
- Commit messages follow Conventional Commits (enforced by commitlint hook).
  Changelog and version bumps are generated — don't edit `CHANGELOG.md` by hand; subject (header) ≤ 100 chars; wrap body/footer lines at ≤ 100.
- Markdown is Prettier-formatted; run `pnpm format` before committing doc-heavy
  changes.

## 6. Never do

- Never edit `docs/guide.md` or `docs/stacks.md` — they are generated by
  `docs/.vitepress/sync.mjs` (and gitignored). Edit the sources instead:
  `template/core/LEAN_AGENT_KIT_GUIDE.md` and
  `template/packs/stacks/.agent/stacks/registry.md`.
- Never edit `CHANGELOG.md` manually (generated by commit-and-tag-version).
- Never bump `version` in `package.json` manually — releases are tag-driven
  (`release.yml` verifies the tag matches and publishes via npm OIDC).
- Never treat `template/core/AGENTS.md` as this repo's instructions; changes
  there alter what every user installs.
- Never commit `docs/.vitepress/dist/`, `docs/.vitepress/cache/`, or
  `node_modules/`.
